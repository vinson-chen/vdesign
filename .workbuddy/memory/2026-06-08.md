## 按钮组件本体论命名改造

### 背景
用户希望结合本地 demo 页面进行可视化优化，点击按钮卡片上的复制按钮时，复制出的内容是基于本体论方法的命名（如 `Button.Primary.Base`）而非旧的 `variant=primary, size=base` 格式。

### 完成内容

**1. 新增本体论命名工具函数**（`src/demo/demos/button-demo.tsx`）

- `ontoName(variant, size)`：将 CVA 的 variant/size 转换为点分本体论名
  - `ontoName("primary", "base")` → `"Button.Primary.Base"`
  - `ontoName("primary", "iconBase")` → `"Button.Primary.Icon.Base"`
  - `ontoName("cell", "cellIconSm")` → `"Button.Cell.Icon.Sm"`（自动去重前缀）

- `buttonItems(variant, textSize, iconSize)`：工厂函数，自动生成 4 个 Card items
  - text → 本体名
  - leftIcon → 本体名.LeftIcon
  - rightIcon → 本体名.RightIcon
  - icon → 纯图标按钮本体名

**2. 重构所有 Card 组件**

- 新增 `ButtonGroup` 组件：统一示例区按钮组布局（text + leftIcon + rightIcon + icon + disabled）
- `buttonItems()` 工厂函数：自动生成 5 个 Card items（新增第 5 个 disabled 项）
- 删除独立的"禁用按钮 disabled"section，禁用态内嵌到每个 variant 卡片中
- 覆盖所有 variant：primary / outline / ghost / destructive / link / cell
- 覆盖所有 size：sm / base / lg 及其 icon/cell 变体

**3. 构建验证通过**
- `tsc --noEmit` 零错误
- `vite build` 成功生成 dist/

### 讨论：本体论命名思路

在改造前讨论了基于本体论（Ontology）思维的组件命名：
- 三层结构：本体类（What）→ 形态变体（Form）→ 规格与状态（Scale & State）
- 关键原则：本体类名对应"最小不可分割概念"；variant=disabled 是状态而非形态，应从 variant 移除
- `data-slot` 是本体论在 DOM 层面的实现
- 建议建立本体词典注释，帮助 AI 和团队成员精准理解组件
